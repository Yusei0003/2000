## 1. 目的・背景

### 1.1 目的

本システムは、年2回（前期＝4〜9月、後期＝10〜翌3月）に作成している日直勤務表（土日祝日・年末年始の当番表）の作成業務を自動化し、以下を実現することを目的とする。

- 手作業による割当作業の省力化
- 複数の割当ルール（間隔日数・ペア重複回避・課除外等）の漏れのない適用
- 担当者交代時の引継ぎの容易化

### 1.2 背景

日直勤務表の作成は、職員名簿・過去の勤務実績・行事日程・育休産休情報など複数の情報を突き合わせて行う必要があり、手作業では時間を要するうえ、ルール適用の漏れが生じやすい。また担当者交代のたびに過去の実績データの引継ぎが課題となっていた。

### 1.3 想定利用者

- 日直勤務表の作成を担当する職員（1名）
- 担当交代時の後任職員

## 2. 適用範囲

### 2.1 対象業務

| 対象 | 内容 |
| --- | --- |
| 対象とする | 日直勤務表の作成、変更届による交代の反映、過去実績の管理、担当交代時の引継ぎ |
| 対象としない | 日直勤務の実施そのもの、勤怠管理、給与計算、変更届の起案・決裁（別システム） |

### 2.2 対象職員

日直の割当対象は**補佐級以下**の職員とする。以下に該当する職員は割当対象から除外する。

- 課長級以上（人事データのランクにより自動判定）
- 外局等（常時除外所属として指定）
- 秘書係（係名により自動判定）
- 運転手（兼職欄により自動判定）
- 会計年度任用職員（区分名により自動判定）
- 派遣（区分名による自動判定、および名簿上の「派遣（除外）」指定）
- 7割措置（再任用短時間等。名簿上の「7割措置（除外）」指定）
- 育児休業・産前産後休暇等の期間中の職員
- 採用から6ヶ月を経過していない新規採用職員
- 性別が未設定の職員（同性ペアのルール上、割当できないため）

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| 処理期 | 勤務表を作成する単位となる半期。前期＝4/1〜9/30、後期＝10/1〜翌3/31。「2026年度 前期」のように表す |
| 指定日 | 日直の割当対象となる日。土曜・日曜・祝日・年末年始閉庁日（12/29〜1/3） |
| 係長級 | 級の一つ。人事データのランク400〜600 |
| 主事級 | 級の一つ。人事データのランク601〜999 |
| ペア | 1日の日直を担当する2名の組合せ。少なくとも1名が係長級であればよく、係長級2名の組合せもある（「係長級1名＋主事級1名」が基本形） |
| 資格要件 | ペアのうち少なくとも1名が係長級または市民課経験者であること（係長級が必ず1名は入るため、実質的には常に満たされる） |
| 課長補佐・副主幹の組合せ回避 | 係長級2名でペアを組む場合、双方の職名が「課長補佐」「副主幹」のいずれかに該当する組合せ（課長補佐＋課長補佐／課長補佐＋副主幹／副主幹＋副主幹）を避けるルール |
| 常時除外所属 | 月や行事に関係なく常に割当対象から外す所属 |
| 枯渇ベース | 女性を優先して割り当て、条件を満たす女性候補が枯渇した場合のみ男性に切り替える方式 |
| 性別ゾーン | 処理期を「女性ゾーン」「男性ゾーン」に分け、一度男性ゾーンに切り替わったらその処理期の残りは女性を割り当てない一方向の切替方式（8.4a節） |
| 要確認 | 制約を緩和して割り当てたが、2名の枠は埋まっている日。担当者による確認が必要 |
| 人数不足エラー | 対象者が不足し、2名の枠を埋められなかった日（1名のみの割当、または誰も割り当てられなかった）。「状態」欄に赤色で表示される |
| 未分類 | 処理期を削除した際に、どの処理期にも紐づかなくなった確定済み履歴 |
| 変更届 | 確定した日直勤務表に対して担当者を交代する際に提出される申請 |

## 4. システム概要

### 4.1 システム形態

| 項目 | 内容 |
| --- | --- |
| 形態 | ブラウザ上で動作するスタンドアロンアプリケーション |
| サーバー | 不要 |
| ネットワーク | 不要（外部通信を一切行わない） |
| データ保存先 | 利用端末のブラウザ localStorage |
| 起動方法 | `index.html` をブラウザで開く |

### 4.2 画面構成

画面上部に処理期セレクタを常時表示し、その下に以下6つのタブを配置する。

| タブ | 主な機能 |
| --- | --- |
| 名簿管理 | Excel名簿の取込、職員名簿の確認・編集、職員の個別登録 |
| ルール設定 | 基本設定、常時除外所属、育休・産休等の除外期間、月別の課除外ルール |
| 行事管理 | 年度別の行事日程・除外所属の登録 |
| 勤務表作成 | 指定日の自動抽出、勤務表の自動作成、確定・履歴保存、CSV/PDF出力 |
| 履歴・確認 | 確定済み履歴の確認、変更届の反映、担当実績の確認、各種出力、バックアップ |
| 使い方 | 操作手順とルールの出典 |

## 5. 業務フロー

### 5.1 通常の勤務表作成（新しい処理期）

```
1. 処理期を追加する（前処理期の「常時除外する所属」を自動引継ぎ）
        ↓
2. 名簿管理タブで、その処理期のExcel名簿を取り込む
   （前処理期の「市民課経験」「派遣」「7割措置」を職員番号単位で自動引継ぎ）
        ↓
3. ルール設定タブで、育休・産休等の除外期間を登録・取込
        ↓
4. 行事管理タブで、その年度の行事日程・除外所属を登録
        ↓
5. 勤務表作成タブで「土日・祝日・年末年始を自動抽出」
        ↓
6.「勤務表を作成する」で自動割当
        ↓
7. 「要確認」の日と未割当職員を確認し、必要に応じて手動調整
        ↓
8.「確定・履歴に保存」
        ↓
9. CSV・PDFで出力し、通知・掲示
```

### 5.2 変更届の反映

```
1. 変更届を受理する
        ↓
2. 履歴・確認タブで該当日の「交代を反映」を押す
        ↓
3. 変更届のテキストを貼り付ける、またはスクリーンショットを読み取る（任意）／交代後の氏名・申請日時を手入力
        ↓
4. 内容を確認して「反映する」
```

### 5.3 過去実績のみの登録

名簿登録や勤務表作成を行わず、過去の日直割だけを登録する場合の流れ。

```
1. 対象年度の処理期を追加する
        ↓
2. 履歴・確認タブの「Excel勤務実績データの取り込み」で過去の勤務表を取り込む
```

### 5.4 担当交代

```
前任者：履歴・確認タブの「引継ぎ用に書き出す」でExcelを出力し、後任者へ受け渡す
        ↓
後任者：自身の端末でExcel名簿を取り込み、続けて引継ぎファイルを
        「Excel勤務実績データの取り込み」で読み込む
        ↓
前任者：ブラウザの閲覧データ削除により localStorage の内容を消去する
```

## 6. 機能要件

### 6.1 処理期管理

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.1.1 | 処理期の選択 | 画面上部のセレクタで処理期を切り替える。切替時、名簿・ルール・勤務表作成の対象期間・履歴の表示が当該処理期の内容に切り替わる |
| 6.1.2 | 処理期の追加 | 年度と区分（前期／後期）を指定して作成する。過去の年度も作成可能。直前の処理期の「常時除外する所属」を自動的に引き継ぐ |
| 6.1.3 | 前回処理期からコピー | 直前の処理期の「常時除外する所属」を、現在の処理期へ再度コピーする |
| 6.1.4 | 処理期の削除 | 処理期そのものを削除する。紐づく確定済み履歴は削除せず「未分類」として残し、ペア重複回避・間隔日数の判定には引き続き使用する |
| 6.1.5 | 過去処理期の案内 | 終了日が本日より前の処理期を選択した場合、案内バナーを表示する |

### 6.2 名簿管理

名簿は**処理期ごとに保持**する。処理期を切り替えると、その処理期の名簿が表示される。

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.2.1 | Excel名簿の取込 | 人事給与システム等から出力した名簿（.xlsx）を取り込む。**選択中の処理期の名簿を取込内容で全置換する**（個別登録した職員も置換対象） |
| 6.2.2 | 前処理期からの引継ぎ | 取込時、前処理期に登録されていた同じ職員番号の「市民課経験」「派遣（除外）」「7割措置（除外）」を自動的に引き継ぐ。引継ぎ結果は件数付きで画面に表示する |
| 6.2.3 | 市民課経験の自動判定 | 取込時、現在の所属が市民課の職員は「市民課経験」を自動的にオンにする |
| 6.2.4 | 所属履歴の記録 | 取込時、前処理期と所属が変わっている場合は前処理期の所属を所属履歴に追加する |
| 6.2.5 | 対象者リスト／除外リスト | 名簿を「対象者リスト」（割当対象）と「除外リスト」（秘書係・運転手・派遣・7割措置・常時除外所属・対象外のいずれかに該当）に分けて表示する。除外リストには除外理由を表示する。両リストとも「身分」「年齢」（Excel取込時の参考情報）と「退職予定日」（編集可能）の列を含む |
| 6.2.6 | 職員検索 | 番号・氏名・所属・係名・職名で名簿を絞り込む |
| 6.2.7 | 個別項目の変更 | 名簿一覧上で「市民課経験」「派遣（除外）」「7割措置（除外）」「退職予定日」を変更する |
| 6.2.8 | 職員の個別登録 | Excel名簿に含まれない職員を個別に追加する。性別は設定できないため、割当対象にはならない。退職予定日は任意で登録できる |
| 6.2.9 | 職員の削除 | 名簿から職員を削除する。確定済み履歴の表示名は残る |
| 6.2.10 | CSV取込／書出 | 簡易形式のCSVによる取込・書出を行う |
| 6.2.11 | 未取込の処理期の扱い | その処理期にまだ名簿が取り込まれていない場合、対象者リスト・除外リストを含む名簿の一覧そのものを表示せず、取込を促すメッセージのみを表示する |
| 6.2.12 | 処理期の名簿の削除 | 選択中の処理期の名簿をすべて削除し、「未取込」の状態に戻す |
| 6.2.13 | Excel取込で除外された人のCSV出力 | 直近のExcel名簿取込で除外された行（区分による除外・級を判定できない・既に退職済み）を、職員番号・区分名・身分・名前・所属名・職名・年齢の列でCSV出力する |
| 6.2.14 | 除外リストの人のCSV出力 | 現在の除外リストを、職員番号・区分名・身分・名前・所属名・職名・年齢・除外理由の列でCSV出力する |

### 6.3 ルール設定

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.3.1 | 基本設定 | 最低間隔日数（既定120日）、新規採用職員の除外期間（既定6ヶ月）、年末年始・GWの遡り回数（既定2回）、ペア重複の遡り年度数（既定2年度）、退職予定日の何ヶ月前まで割当対象とするか（既定1ヶ月） |
| 6.3.2 | 資格要件 | 設定不要。ペアのうち少なくとも1名が係長級または市民課経験者であることを常に適用する |
| 6.3.3 | 常時除外する所属 | 名簿に登録済みの所属からチェックボックスで選択する（所属CD順に表示）。処理期ごとに保持する |
| 6.3.4 | 育休・産休等の除外期間 | 育休一覧・産休一覧のExcel取込、および職員番号・開始日・終了日による個別登録。終了日が未定の場合は空欄で登録でき、復帰まで対象外として扱う |
| 6.3.5 | 除外期間の重複排除 | 同じ職員・同じ期間の行は取込時に自動的にスキップする |
| 6.3.6 | 名簿外職員の除外 | 名簿にない職員番号の行は取込対象外とし、個別登録も受け付けない |
| 6.3.7 | 除外期間の絞り込み表示 | 一覧には選択中の処理期と期間が重なる行のみ表示する |
| 6.3.8 | 月別の課除外ルール | 月と所属の組合せで除外ルールを登録する。既定値として10・11月の商工観光課／広報係、12・1月のふるさと納税係、1〜4月の税務課を設定する |

### 6.4 行事管理

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.4.1 | 行事の登録 | 年度ごとに行事名・行事日・終了日・除外リードタイム（既定30日）・除外する所属を登録する |
| 6.4.2 | 行事テンプレート | 産業まつり・花火大会・選挙・成人式等の候補を入力補助として提供する |
| 6.4.3 | 除外開始日の自動計算 | 行事日とリードタイムから除外開始日を自動計算する |
| 6.4.4 | 前年度の行事をコピー | 前年度の行事名・除外所属・リードタイムを引き継いで作成する（日付は空欄） |
| 6.4.5 | 前年度の登録状況（参考） | 前年度の行事一覧を読み取り専用で参考表示する |

### 6.5 勤務表作成

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.5.1 | 対象期間の自動入力 | 選択中の処理期の開始日・終了日を自動的に入力する |
| 6.5.2 | 指定日の自動抽出 | 対象期間から土曜・日曜・祝日・年末年始閉庁日を抽出する。確定済み履歴に含まれる日は除く |
| 6.5.3 | 抽出0件時の案内 | 抽出結果が0件の場合、その理由（全て確定済み／対象日なし）を表示する |
| 6.5.4 | 指定日の除外 | 抽出された日のうち不要な日をチェックボックスで対象から外す |
| 6.5.5 | 勤務表の自動作成 | 第8章の割当ルールに基づき、各指定日に2名（少なくとも1名は係長級。係長級2名の組合せもある）を割り当てる。日直のペアは性別ゾーン（8.4a節）に従い、いったん男性ゾーンに切り替わったら以後その処理期では女性を割り当てない。通常の組合せが組めない場合は、人数不足を可能な限り防ぐため第8.4b節の最終手段により、その時点のゾーンの性別に固定したまま対象者を自動で最大限（2名、無理なら1名）割り当てる |
| 6.5.6 | 状態の表示 | 各日を「OK」「要確認：（理由）」「エラー：（理由）」のいずれかで表示する。要確認の行は黄色、エラー（2名の枠を埋められなかった日）の行は赤色で強調表示する |
| 6.5.7 | 手動調整（プルダウン） | 各日の1人目（係長級）・2人目（係長級・主事級）をプルダウンで変更する。1人目は係長級のみ、2人目は係長級・主事級のどちらも選択できる |
| 6.5.7a | 手動調整（ドラッグ） | 結果一覧の各欄に表示された職員名の札をドラッグして、別の日・別の欄（列をまたいでも可）の職員と入れ替えられる |
| 6.5.7b | 手動調整後の再判定 | プルダウン変更・ドラッグ入れ替えのいずれの場合も、変更後の組合せを次の観点で再判定する：片方が未定でないか（未定なら人数不足エラー）、係長級が含まれているか、性別が一致しているか、同一課でないか、課長補佐・副主幹の組合せでないか、同一処理期内で2回目の割当になっていないか。違反があれば「要確認」または「エラー」として理由を表示する |
| 6.5.8 | 未割当職員の表示 | 結果一覧の下に、今期まだ一度も割り当てられていない対象職員と、その理由を一覧表示する |
| 6.5.8a | 担当回数が多い職員の表示 | 結果一覧の下に、今期の担当回数が2回以上の職員を、回数の多い順に一覧表示する。最大担当回数・平均担当回数・2回以上の人数も表示する |
| 6.5.9 | 確定・履歴に保存 | 作成内容を確定し、処理期に紐づけて履歴に保存する |
| 6.5.10 | CSV出力 | 作成内容をCSVで出力する |
| 6.5.11 | PDF出力 | 作成内容をPDFで出力する。処理期の期間を前半3ヶ月・後半3ヶ月の2つに分け、それぞれを指定のページにまとめる（前期：1ページ目＝4〜6月／2ページ目＝7〜9月。後期：1ページ目＝10〜12月／2ページ目＝1〜3月）。該当日がない期間もページとして出力する |

### 6.6 履歴・確認

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.6.1 | 確定済み履歴の表示 | 確定済みの勤務表を一覧表示する。表示フィルタの既定は選択中の処理期。「全期間」「未分類」「各処理期」に切り替えられる |
| 6.6.2 | 変更届の反映 | 該当日の係長級／主事級について、交代後の職員と申請日時を登録する |
| 6.6.3 | 変更届のOCR読取 | 変更申請のスクリーンショット画像から交代相手氏名・申請日時・変更する日付・申請者を読み取り、入力欄に下書きする。読取結果は確認・修正のうえ反映する |

## 8. 割当ルール仕様

### 8.2 ペアの構成

各指定日に、**2名**（1人目・2人目）を割り当てる。**1人目は必ず係長級**とし、**2人目は係長級・主事級のいずれでもよい**（少なくとも1名が係長級であればよいため）。「係長級1名・主事級1名」が基本の組合せだが、状況に応じて係長級2名の組合せにもなる。

| 第3段階 | 緩和 | 緩和 | 適用 | 適用 | 要確認：課長補佐・副主幹の組合せになっています |
| 第4段階 | 緩和 | 緩和 | 緩和 | 適用 | 要確認：同一課の組合せになっています |
| 第5段階 | 緩和 | 緩和 | 緩和 | 緩和 | 要確認：資格要件を満たす職員がいません |

第1〜5段階・最終手段はいずれも「女性のみ」または「男性のみ」の同性ペアで探索する（枯渇ベース、8.1節）。

### 8.4a 性別ゾーン（女性ゾーン→男性ゾーンの一方向切替）

処理期の中で「女性ゾーン」「男性ゾーン」という状態を持ち、**一度男性ゾーンに切り替わったら、その処理期の残りは女性を一切探索しない**（一方向のみで、女性ゾーンへは戻らない）。男性の期間の途中に女性が単発で混ざると担当交代がしづらくなるため、ゾーンをまたいだ混在を構造的に起こさないようにしている。

| ゾーン | 探索順 |
| --- | --- |
| 女性ゾーン | ①女性・今期未割当 のみ |
| 男性ゾーン | ②男性・今期未割当 → ③男性・今期2回目 → ④最終手段（男性に固定したまま、係長級の有無・最低間隔日数を緩和） |

**ゾーンの境界＝「その日に割り当てられる未割当の女性が1人もいなくなった日」。** 女性ゾーンで①が失敗した日に限り、その同じ日から男性ゾーンの②〜④を試す。②〜④のいずれかで男性のペア（またはやむを得ず1名のみ）が見つかれば、その日から男性ゾーンへ切り替わり、以後この処理期では女性を二度と探索しない。

**②〜④のいずれも失敗した場合（＝そもそも男性が存在しない、または全員が対象外）は、ゾーンを切り替えても意味がないため、女性側の「今期2回目」・最終手段（女性に固定したまま係長級の有無・最低間隔日数を緩和）を試す。** この場合、女性ゾーンにとどまり続ける（全員女性の職場等での安全策）。

**安全弁：** 女性を一度も使っていない状態（＝処理期の冒頭、まだ女性ゾーンが実質的に始まっていない状態）で、行事除外等によりたまたま1日だけ女性が0人になっても、その1日だけでは男性ゾーンに固定しない。女性を一度でも使ったあとで①が失敗した場合に限り、男性ゾーンへの切替がその処理期の残り全体に定着する。

前半・後半に分けて処理期を作成する場合など、続きを生成する際は、その処理期の確定済み履歴から性別ゾーンの状態を復元する（履歴に女性が含まれていれば「女性を使用済み」、履歴の最後が男性のみであれば「男性ゾーン」として開始する）。

**性別ごとの日数の枠は設けない。** 各性別に割り当てられる日数は、その処理期の男女の人数に応じて自然に決まる（女性が少ない職場では、女性ゾーンの期間が短く、男性ゾーンの期間が長くなる）。

### 8.4b 人数不足時の最終手段（ゾーン内に固定）

女性ゾーン・男性ゾーンいずれの場合も、8.4a節の最終手段（③④、または女性側の同等の最終手段）は**その時点のゾーンの性別に固定したまま**行う。性別を問わない・他方の性別で埋める、という処理は行わない。

| ケース | 割当内容 | 状態 |
| --- | --- | --- |
| 係長級がいる（ゾーン内） | その係長級と、担当回数の少ない同性の候補を組み合わせる | 要確認：人数不足のため、通常のルールを緩和して割り当てました |
| 係長級が1名もいない（ゾーン内） | 担当回数の少ない同性の候補2名を組み合わせる | 要確認：係長級が含まれていません（人数不足のため） |
| ゾーン内の対象者が1名しかいない | その1名のみを割り当てる | エラー：人数不足のため1名のみの割当です |
| ゾーン内の対象者が1名もいない | 誰も割り当てない | エラー：対象者がいません |

**男性ゾーンで男性が本当に枯渇した日は、女性で埋めずにエラー（赤色）とする。** 女性混入をゼロにすることを、人数不足によるエラー表示の発生よりも優先した設計判断である。

この最終手段は2段階で行う。まず**最低間隔日数（既定120日）を守ったまま**上表の判定を行い、それでも対象者が1名も残らない場合に限り、**最低間隔日数の判定も外して**同じ判定をやり直す（性別は変えない）。後者で割り当てた場合は「要確認：前回勤務日から120日未満の職員を含みます（人数不足のため）」を表示する。

この最終手段により2名の枠が埋まった場合は「要確認」（黄色）、1名のみ・0名の場合は「エラー」（赤色）として状態欄に表示する。

### 8.5 候補の優先順位

1人目（係長級）の候補は、資格要件を満たす者を優先しつつ、累計担当回数の少なさ・前回勤務日の古さ（担当履歴のない職員を最優先）の順に並べて先頭から評価する。

2人目の候補（係長級・主事級を問わない）は、**級による優先は行わず**、累計担当回数の少なさ・前回勤務日の古さのみで並べて評価する。これにより、係長級2名の組合せと係長級＋主事級の組合せが、担当回数等の実績に基づいて対等に扱われる。

累計担当回数による並べ替えにより、ある処理期で割り当てられなかった職員は次の処理期で優先される。

### 8.6 市民課経験の判定

以下のいずれかに該当する場合、市民課経験ありとする。

1. 名簿上で「市民課経験」がオンになっている
2. 現在の所属名に「市民課」を含む
3. 所属履歴に「市民課」を含む所属がある

なお、Excel名簿の取込時に上記2に該当する職員は「市民課経験」が自動的にオンになり、以後の処理期にも引き継がれる。

### 8.7 未割当職員の理由判定

今期まだ割り当てられていない対象職員について、対象日ごとに以下を積み上げて理由を表示する。

| 理由 | 判定 |
| --- | --- |
| 性別が未設定 | 性別が設定されていない |
| 育休・産休等の除外期間中 | 対象日が登録された除外期間内 |
| 所属の除外ルールに該当 | 対象日に所属が月別・行事別の除外対象 |
| 採用から6ヶ月未満 | 対象日が採用日＋6ヶ月より前 |
| 退職予定日の1ヶ月前を過ぎている | 対象日が退職予定日から設定ヶ月数を引いた日より後 |
| 前回勤務日から120日未満 | 対象日が前回勤務日＋120日より前 |
| 年末年始・GWの重複回避 | 対象日が年末年始・GWで、過去の同期間の担当者に該当する |
| 今期の割当枠が埋まった | 候補ではあったが、他の職員が優先された |
| 自分のゾーンでなかった日 | その日は性別ゾーン（8.4a節）が自分の性別ではなかった（「女性ゾーンでなかった日」／「男性ゾーンでなかった日」として表示） |

本機能は完全なシミュレーションではなく、職員個人の属性による除外の積み上げによる推定である。同一課回避・ペア重複回避などペア単位の制約は理由に反映せず、「今期の割当枠が埋まった」に含まれる。

## 10. 制約事項

| No | 制約 |
| --- | --- |
| 10.1 | データはブラウザ（端末）ごとの localStorage に保存されるため、他の端末とは共有されない |
| 10.2 | ブラウザの閲覧データを削除するとデータが消去される。定期的なバックアップが必要 |
| 10.3 | 祝日は計算式による自動判定であり、法改正や臨時の祝日には対応しない。作成後の確認が必要 |
| 10.4 | 自動割当は補助であり、「要確認」の日や組織の実情に応じた調整は手動で行う |
| 10.5 | PDF出力は画面表示を画像化する方式のため、PDF内の文字はコピーできない |
| 10.6 | 変更届のOCR読取機能（スクリーンショットからの読取）は、`python3 -m http.server` 等でファイルを配信して開いた場合のみ使用できる。`index.html` を直接開いた場合（`file://`）はブラウザの制約により使用できない。**テキストの貼り付けによる読取はこの制約を受けず、`file://` でも使用できる**。この場合も手入力での交代反映は使用できる |
| 10.7 | OCRの読取結果は誤読することがある（特に人名の漢字）。必ず内容を確認してから反映する |
| 10.7a | テキスト貼り付けは、貼り付けた文章の中から「交代相手氏名」「申請日」「変更する日付」「申請者」の各ラベルの直後（同じ行の続き、またはラベルのみの行なら次の行）の文字列を抽出する方式のため、これらのラベル文言を含まない形式の文章では読み取れない |
| 10.8 | 性別はExcel名簿の取込時にのみ自動設定される。個別登録した職員は性別が未設定となり、割当対象にならない |
| 10.9 | Excel名簿の取込は選択中の処理期の名簿を全置換するため、個別登録した職員も置換対象となる |

## 11. ルールの出典

本システムが実装する割当ルールは、「日直勤務表の作成及び変更等についてのマニュアル」および追加仕様確認書に基づく。

| No | ルール |
| --- | --- |
| 1 | 補佐級以下が対象。外局・秘書・運転手・会計年度任用職員・派遣・7割措置・育休/産休等の期間中の職員は除く。新規採用職員は採用から6ヶ月経過後から対象 |
| 2 | 1日2名のうち少なくとも1名が係長級であればよい（係長級1名＋主事級1名が基本だが、係長級2名の組合せもある）。日直のペアは同性とし、女性を優先して割り当てる。処理期の中で女性ゾーンから男性ゾーンへ一方向に切り替わり（8.4a節）、いったん男性ゾーンに入ったら以後その処理期では女性を割り当てない。毎日の組合せのうち少なくとも1名は係長級または市民課経験者であること。同じ職場同士は組み合わせない |
| 3 | 各行事の除外期間（リードタイムを含む）は担当課を除外する。10・11月は商工観光課・広報係、12・1月はふるさと納税係、1〜4月は税務課を除外 |
| 4 | 年末年始（12/29〜1/3）・ゴールデンウィークは前回・前々回と同じ職員にならないよう配慮する |
| 5 | ペアは過去2年度以内の重複を避ける。ただし変更届による交代は対象外とする |
| 6 | 前回勤務日から120日以上間隔を空ける |
| 7 | 同一処理期内は原則1人1回の割当とする（該当する候補が枯渇した場合に限り、その期2回目の割当を許可する） |
| 8 | 係長級2名でペアを組む場合、双方の職名が「課長補佐」「副主幹」のいずれかに該当する組合せ（課長補佐＋課長補佐／課長補佐＋副主幹／副主幹＋副主幹）は避ける |
