## 1. 目的・背景

### 1.1 目的

本システムは、年2回（前期＝4〜9月、後期＝10〜翌3月）に作成している日直勤務表（土日祝日・年末年始の当番表）の作成業務を自動化し、以下を実現することを目的とする。

- 手作業による割当作業の省力化
- 複数の割当ルール（間隔日数・ペア重複回避・課除外等）の漏れのない適用
- 担当者交代時の引継ぎの容易化

### 1.2 背景

日直勤務表の作成は、職員名簿・過去の勤務実績・行事日程・育休産休情報など複数の情報を突き合わせて行う必要があり、手作業では時間を要するうえ、ルール適用の漏れが生じやすい。また担当者交代のたびに過去の実績データの引継ぎが課題となっていた。

### 1.3 想定利用者

- 日直勤務表の作成を担当する職員（1名）
- 担当交代時の後任職員

## 2. 適用範囲

### 2.1 対象業務

| 対象 | 内容 |
| --- | --- |
| 対象とする | 日直勤務表の作成、変更届による交代の反映、過去実績の管理、担当交代時の引継ぎ |
| 対象としない | 日直勤務の実施そのもの、勤怠管理、給与計算、変更届の起案・決裁（別システム） |

### 2.2 対象職員

日直の割当対象は**補佐級以下**の職員とする。以下に該当する職員は割当対象から除外する。

- 課長級以上（人事データのランクにより自動判定）
- 外局等（常時除外所属として指定）
- 秘書係（係名により自動判定）
- 運転手（兼職欄により自動判定）
- 会計年度任用職員（区分名により自動判定）
- 派遣（区分名による自動判定、および名簿上の「派遣（除外）」指定）
- 7割措置（再任用短時間等。名簿上の「7割措置（除外）」指定）
- 育児休業・産前産後休暇等の期間中の職員
- 採用から6ヶ月を経過していない新規採用職員
- 性別が未設定の職員（同性ペアのルール上、割当できないため）

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| 処理期 | 勤務表を作成する単位となる半期。前期＝4/1〜9/30、後期＝10/1〜翌3/31。「2026年度 前期」のように表す |
| 指定日 | 日直の割当対象となる日。土曜・日曜・祝日・年末年始閉庁日（12/29〜1/3） |
| 係長級 | 級の一つ。人事データのランク400〜600 |
| 主事級 | 級の一つ。人事データのランク601〜999 |
| ペア | 1日の日直を担当する2名の組合せ。少なくとも1名が係長級であればよく、係長級2名の組合せもある（「係長級1名＋主事級1名」が基本形） |
| 資格要件 | ペアのうち少なくとも1名が係長級または市民課経験者であること（係長級が必ず1名は入るため、実質的には常に満たされる） |
| 課長補佐・副主幹の組合せ回避 | 係長級2名でペアを組む場合、双方の職名が「課長補佐」「副主幹」のいずれかに該当する組合せ（課長補佐＋課長補佐／課長補佐＋副主幹／副主幹＋副主幹）を避けるルール |
| 常時除外所属 | 月や行事に関係なく常に割当対象から外す所属 |
| 枯渇ベース | 女性を優先して割り当て、条件を満たす女性候補が枯渇した場合のみ男性に切り替える方式 |
| 性別ゾーン | 処理期を「女性ゾーン」「男性ゾーン」に分け、一度男性ゾーンに切り替わったらその処理期の残りは女性を割り当てない一方向の切替方式（8.4a節） |
| 要確認 | 制約を緩和して割り当てたが、2名の枠は埋まっている日。担当者による確認が必要 |
| 人数不足エラー | 対象者が不足し、2名の枠を埋められなかった日（1名のみの割当、または誰も割り当てられなかった）。「状態」欄に赤色で表示される |
| 未分類 | 処理期を削除した際に、どの処理期にも紐づかなくなった確定済み履歴 |
| 変更届 | 確定した日直勤務表に対して担当者を交代する際に提出される申請 |
| 決裁 | 勤務表の内容を確定する前に、責任者が内容を確認・承認すること。本システムでは、確定操作の前に「決裁が完了したことを確認しました」というチェックで、決裁が完了したことを担当者自身が確認する |
| 引き戻し | 確定済みの勤務表を、修正可能な状態へ戻す操作。確定済み履歴からその回の確定分を削除する一方、引き戻し前の内容は「作成履歴」として保持される |

## 4. システム概要

### 4.1 システム形態

| 項目 | 内容 |
| --- | --- |
| 形態 | ブラウザ上で動作するスタンドアロンアプリケーション |
| サーバー | 不要 |
| ネットワーク | 不要（外部通信を一切行わない） |
| データ保存先 | 利用端末のブラウザ localStorage |
| 起動方法 | `index.html` をブラウザで開く |

### 4.2 画面構成

画面上部に処理期セレクタを常時表示し、その下に以下6つのタブを配置する。

| タブ | 主な機能 |
| --- | --- |
| 名簿管理 | Excel名簿の取込、職員名簿の確認・編集、CSV取込 |
| ルール設定 | 基本設定、常時除外所属、育休・産休等の除外期間、月別の課除外ルール |
| 行事管理 | 年度別の行事日程・除外所属の登録 |
| 勤務表作成 | 指定日の自動抽出、勤務表の自動作成、確定・履歴保存、CSV/PDF出力 |
| 履歴・確認 | 確定済み履歴の確認、変更届の反映、担当実績の確認、各種出力、バックアップ |
| 使い方 | 新しい処理期での作成手順（確定前の入替を含む）、変更届による交代の反映、ルールの出典、その他の操作手順（引き戻して修正 等、ボタンで開閉） |

タブとは別に、画面右下に常時表示される「使い方アシスタント」ボタンから、キーワードや文章で質問できるアプリ内検索型チャットボットを開ける（4.3節）。

### 4.3 使い方アシスタント（アプリ内検索型チャットボット）

画面右下に常時表示されるボタンから開けるチャット風のパネル。使い方が分からない、何ができるか分からないときにキーワードや文章で質問すると、埋め込み済みの「使い方」タブ・仕様書・設計書の中から関連しそうな見出しを検索して提示する。

- **よくある質問チップ**：パネルを開いた直後と、検索結果が0件だったときに、「勤務表を作る」「変更届を反映する」「PDFを出力する」等のボタンを表示する。押すとその文言でそのまま検索する。
- **使い方タブを優先表示**：使い方タブの内容がヒットした場合はそれを優先して表示し、仕様書・設計書の該当箇所は「詳しい資料も見る（件数）」の折りたたみに回す。使い方タブに該当が無い場合のみ、仕様書・設計書を通常表示する（使い方タブは平易な案内文であるのに対し、仕様書・設計書は章番号や専門的な記述が多いため）。
- **本文抜粋とハイライト**：各結果に本文の抜粋（ヒットした語の周辺）を表示し、検索語およびその言い換え語に一致する部分を太字＋着色でハイライトする。
- **その場で本文を開く**：結果を押すと、画面を切り替えずにチャット内でその場に本文全文（先頭500文字まで）を展開する。あわせて表示される「この場所を画面で開く」を押すと、初めて該当タブ・該当箇所へ実際に移動する（使い方タブの折りたたまれた「その他使い方」は自動的に展開される）。
- **同義語辞書による言い換え**：「エクセル」→xlsx/Excel/エクスポート、「印刷」→PDF/出力、「交換」→交代/変更届 等、ユーザーが入力しがちな言葉から実際に文書中で使われている語へあらかじめ言い換えて検索する。ヒット判定・ハイライトの両方に反映される。

外部のAI APIには接続しない。日本語は分かち書きされていないため、形態素解析の代わりに文字バイグラム（連続2文字の集合）の一致数によるスコアリングで検索する簡易的な方式。見出しとの一致を本文との一致より重く評価し、完全な部分一致にはボーナスを与える。クエリ（および同義語展開した言い換え語）のバイグラムのうち一定割合（34%）以上が同じセクションにまとまって含まれる場合（または完全な部分一致の場合）のみ候補として採用し、無関係な文字列が巨大な文書のどこかとたまたま一致してヒットしてしまうことを防ぐ。

使い方タブのセクション本文は、見出し要素の「次の兄弟要素」ではなく、見出しの直後から（ネストの深さに関係なく）文書順で次の見出しの直前までをDOM Rangeで取り出して構築する。これは、「その他使い方」のような大枠の見出しの直下に、複数のh3見出しが入れ子のDOM構造で配置されているため、単純に兄弟要素を辿ると大枠の見出しが配下の全セクションの本文を丸ごと抱え込み、ほぼどんな検索語にもヒットしてしまう巨大セクションになるのを防ぐため。

## 5. 業務フロー

### 5.1 通常の勤務表作成（新しい処理期）

```
1. 処理期を追加する（前処理期の「常時除外する所属」を自動引継ぎ）
        ↓
2. 名簿管理タブで、その処理期のExcel名簿を取り込む
   （前処理期の「市民課経験」「派遣」「7割措置」を職員番号単位で自動引継ぎ）
        ↓
3. ルール設定タブで、育休・産休等の除外期間を登録・取込
        ↓
4. 行事管理タブで、その年度の行事日程・除外所属を登録
        ↓
5. 勤務表作成タブで「土日・祝日・年末年始を自動抽出」
        ↓
6.「勤務表を作成する」で自動割当
        ↓
7. 「要確認」の日と未割当職員を確認し、必要に応じて手動調整
        ↓
8. 勤務表の内容を確認・決裁する（決裁後、「決裁が完了したことを確認しました」にチェック）
        ↓
9.「確定・履歴に保存」（以後、内容は保持されたまま編集ロックされる）
        ↓
10. CSV・PDFで出力し、通知・掲示
        （確定後に修正が必要な場合は「引き戻して修正」→再調整→再度8.から）
```

### 5.2 変更届の反映

```
1. 変更届を受理する
        ↓
2. 履歴・確認タブで該当日の「交代を反映」を押す
        ↓
3. 変更届のテキストを貼り付ける、またはスクリーンショットを読み取る（任意）／交代後の氏名・申請日時を手入力
        ↓
4. 内容を確認して「反映する」
```

### 5.3 過去実績のみの登録

名簿登録や勤務表作成を行わず、過去の日直割だけを登録する場合の流れ。

```
1. 対象年度の処理期を追加する
        ↓
2. 履歴・確認タブの「Excel勤務実績データの取り込み」で過去の勤務表を取り込む
```

### 5.4 担当交代

```
前任者：履歴・確認タブの「引継ぎ用に書き出す」でExcelを出力し、後任者へ受け渡す
        ↓
後任者：自身の端末でExcel名簿を取り込み、続けて引継ぎファイルを
        「Excel勤務実績データの取り込み」で読み込む
        ↓
前任者：ブラウザの閲覧データ削除により localStorage の内容を消去する
```

## 6. 機能要件

### 6.1 処理期管理

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.1.1 | 処理期の選択 | 画面上部のセレクタで処理期を切り替える。切替時、名簿・ルール・勤務表作成の対象期間・履歴の表示が当該処理期の内容に切り替わる |
| 6.1.2 | 処理期の追加 | 年度と区分（前期／後期）を指定して作成する。過去の年度も作成可能。直前の処理期の「常時除外する所属」を自動的に引き継ぐ |
| 6.1.3 | 前回処理期からコピー | 直前の処理期の「常時除外する所属」を、現在の処理期へ再度コピーする |
| 6.1.4 | 処理期の削除 | 処理期そのものを削除する。紐づく確定済み履歴は削除せず「未分類」として残し、ペア重複回避・間隔日数の判定には引き続き使用する |
| 6.1.5 | 過去処理期の案内 | 終了日が本日より前の処理期を選択した場合、案内バナーを表示する |

### 6.2 名簿管理

名簿は**処理期ごとに保持**する。処理期を切り替えると、その処理期の名簿が表示される。

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.2.1 | Excel名簿の取込 | 人事給与システム等から出力した名簿（.xlsx）を取り込む。**選択中の処理期の名簿を取込内容で全置換する**（CSV取込した職員も置換対象） |
| 6.2.2 | 前処理期からの引継ぎ | 取込時、前処理期に登録されていた同じ職員番号の「市民課経験」「派遣（除外）」「7割措置（除外）」「選挙管理委員会（併任）」を自動的に引き継ぐ。引継ぎ結果は件数付きで画面に表示する。対象者リストの上に、これらの項目が自動的に引き継がれる旨と、取込後に内容を確認するよう促す注意書きを常時表示する |
| 6.2.3 | 市民課経験の自動判定 | 取込時、現在の所属が市民課の職員は「市民課経験」を自動的にオンにする |
| 6.2.4 | 所属履歴の記録 | 取込時、前処理期と所属が変わっている場合は前処理期の所属を所属履歴に追加する |
| 6.2.5 | 対象者リスト／除外リスト | 名簿を「対象者リスト」（割当対象）と「除外リスト」（秘書係・運転手・派遣・7割措置・常時除外所属・対象外のいずれかに該当）に分けて表示する。除外リストには除外理由を表示する。両リストとも「身分」「年齢」（Excel取込時の参考情報）、「選挙管理委員会（併任）」、「退職予定日」（編集可能）の列を含む |
| 6.2.6 | 職員検索 | 番号・氏名・所属・係名・職名で名簿を絞り込む |
| 6.2.7 | 個別項目の変更 | 名簿一覧上で「市民課経験」「派遣（除外）」「7割措置（除外）」「選挙管理委員会（併任）」「退職予定日」を変更する |
| 6.2.9 | 職員の削除 | 名簿から職員を削除する。確定済み履歴の表示名は残る |
| 6.2.10 | CSV取込／書出 | 簡易形式のCSVによる取込・書出を行う |
| 6.2.11 | 未取込の処理期の扱い | その処理期にまだ名簿が取り込まれていない場合、対象者リスト・除外リストを含む名簿の一覧そのものを表示せず、取込を促すメッセージのみを表示する |
| 6.2.12 | 処理期の名簿の削除 | 選択中の処理期の名簿をすべて削除し、「未取込」の状態に戻す |
| 6.2.13 | Excel取込で除外された人のCSV出力 | 直近のExcel名簿取込で除外された行（区分による除外・級を判定できない・既に退職済み）を、職員番号・区分名・身分・名前・所属名・職名・年齢の列でCSV出力する |
| 6.2.14 | 除外リストの人のCSV出力 | 現在の除外リストを、職員番号・区分名・身分・名前・所属名・職名・年齢・除外理由の列でCSV出力する |

### 6.3 ルール設定

| No | 機能 | 内容 |
| --- | --- | --- |
| 6.3.1 | 基本設定 | 最低間隔日数（既定120日）、新規採用職員の除外期間（既定6ヶ月）、年末年始・GWの遡り回数（既定2回）、ペア重複の遡り年度数（既定2年度）、退職予定日の何ヶ月前まで割当対象とするか（既定1ヶ月） |
| 6.3.2 | 資格要件 | 設定不要。ペアのうち少なくとも1名が係長級または市民課経験者であることを常に適用する |
| 6.3.3 | 常時除外する所属 | 名簿に登録済みの所属からチェックボックスで選択する（所属CD順に表示）。処理期ごとに保持する |
| 6.3.4 | 育休・産休・病気休暇の除外期間 | 育休一覧・産休一覧・病気休暇一覧のExcel取込のみに対応する（個別の手入力登録は廃止）。病気休暇Excelは職員番号・氏名・病名・開始・終了の列を読み取り、「区分」欄には病名をそのまま表示する。終了日が未定の場合は空欄のまま取り込まれ、復帰まで対象外として扱う |
| 6.3.4a | 産休終了後の育休みなし | 産休（産休Excelの取込）は、終了日を過ぎても、その職員の育休（育休Excelの取込）が別途登録されていない限り対象外を継続する。産休終了後は必ず育休に入るという前提で、育休情報がまだ登録されていない場合でも割り当てないようにするため。育休が登録されれば、以降はその育休記録自体の開始日・終了日で対象外期間を判定する |
| 6.3.4b | 長期病気休暇の延長確認チェックリスト | 病気休暇は実績ベースで登録され、処理期作成時点では処理期内の病気休暇がまだ登録されていないことが多い。**ひとつ前の処理期に病気休暇（Excel取込のみが対象）で合計15日以上休んでいた職員**を延長の可能性がある候補として一覧にし、チェックできるようにする。同一職員の複数の病気休暇記録は前期分を合算し、終了日が未登録の休暇は前期末まで続いたものとして数える。チェックした職員は、登録されている病気休暇の終了日に関係なく、この処理期の間ずっと割当対象から除外する（チェック状態は処理期ごとに保持する）。チェックしなければ、登録されている終了日どおりに扱われる |
| 6.3.5 | 除外期間の重複排除 | 同じ職員・同じ期間の行は取込時に自動的にスキップする |
| 6.3.6 | 名簿外職員の除外 | 名簿にない職員番号の行は取込対象外とする |
| 6.3.7 | 除外期間の絞り込み表示 | 一覧には選択中の処理期と期間が重なる行のみ表示する |
| 6.3.8 | 月別の課除外ルール | 月と所属の組合せで除外ルールを登録する。既定値として10・11月の商工観光課／広報係、12・1月のふるさと納税係、1〜4月の税務課を設定する |
| 6.3.9 | 特例の除外（個別） | 自動判定ではカバーできない理由（例：前の処理期で2回勤務した、体調不良が続いている等）で、選択中の処理期の名簿から職員を選び、理由を添えて個別に割当対象から除外する。理由は必須。登録した職員は、選択中の処理期の間ずっと割当対象から除外される（8.3.4c節）。処理期ごとに保持する |

| 6.5.8 | 未割当職員の表示 | 結果一覧の下に、今期まだ一度も割り当てられていない対象職員と、その理由を一覧表示する |

| 6.5.9 | 決裁確認 | 「勤務表の内容を確認・決裁してから確定してください。」の注意書きを常時表示する。「決裁が完了したことを確認しました」のチェックを入れないと確定できない。作成内容を変更した場合（自動作成のやり直し・指定日の対象変更・プルダウン変更・ドラッグ入れ替え）は、チェックが自動的に外れ、確定前に改めて確認を求める |

### 7.6 PDF出力の仕組み（ファイルサイズ対策）

以前は画面上の表をhtml2canvasで画像（PNG）として撮影し、jsPDFに貼り付ける方式で作成していたため、行数・ページ数が増えるとファイルサイズが数MBまで大きくなりやすかった。現在はjsPDFの描画機能（文字・矩形・線・丸）を使い、表の罫線・見出し・氏名・日付などをPDF内に直接ベクター（文字・図形の命令）として描画する方式に変更している。

- **フォントの埋め込み**：日本語を描画するため、Noto Sans JP（SIL Open Font License）をアプリに同梱し（`vendor/notosansjp-regular.b64.js`）、PDF生成時にjsPDFへ登録する。jsPDFはフォントのうち実際にそのPDFで使われた文字（グリフ）だけを自動的に選び出して埋め込む（サブセット化）ため、同梱しているフォント自体は大きくても、生成されるPDFのサイズは実際に使われた氏名・日付等の文字数に応じた小さいものになる。
- **ストリーム圧縮**：jsPDFの`compress`オプションを有効にし、フォント・罫線・文字の描画命令をPDF内部でロスレス圧縮する。見た目には影響しない。
- **列幅の自動調整**：各列の幅は、実際のセル内容（氏名・日付・変更日時など）の文字幅から自動的に決める。基準の文字サイズで用紙の横幅に収まる場合はそのまま横幅いっぱいに広げ、収まらない場合（氏名等が非常に長い場合）は文字サイズごと縮小して収める。
- **効果**：文字を画像ではなく実際の文字データとして埋め込むため、PDF内の文字はコピー・検索ができるようになった。ファイルサイズは、数百件規模の履歴PDFでも数百KB程度に収まる。

### 8.4 段階的緩和

すべての制約を満たす組合せが見つからない場合、以下の順に制約を緩和して再探索する。
**同一課回避（8.3.13）・ペア重複回避（8.3.11）・資格要件（8.3.14）は通常の探索では緩和しない（マスト）。**
緩和するのは職名の組合せ（課長補佐・副主幹）だけで、それ以外は「その日の2名を埋められない」場合の
最終手段でのみ緩和する。

**通常の探索**

| 段階 | ペア重複回避 | 同一課回避 | 資格要件 | 課長補佐・副主幹の組合せ回避 | 状態 |
| --- | --- | --- | --- | --- | --- |
| 第1段階 | 適用 | 適用 | 適用 | 適用 | OK |
| 第2段階 | 適用 | 適用 | 適用 | 緩和 | 要確認：課長補佐・副主幹の組合せになっています |

**人数不足時の最終手段**（第1〜2段階でその日の2名を埋められない場合だけ使う。空き枠＝人数不足エラーにするよりは、という位置づけのため、被害の小さい順に緩めていく）

| 段階 | ペア重複回避 | 同一課回避 | 資格要件 | 状態 |
| --- | --- | --- | --- | --- |
| 最終手段① | 緩和 | 適用 | 適用 | 要確認：過去のペアと重複しています |
| 最終手段② | 緩和 | 緩和 | 適用 | 要確認：同一課の組合せになっています |
| 最終手段③ | 緩和 | 緩和 | 緩和 | 要確認：資格要件を満たす職員がいません |

最終手段でも、いきなり候補の先頭2名を機械的に取るのではなく、上表の順に「できるだけ避けた組合せ」から探す。
これらの段階・最終手段はいずれも「女性のみ」または「男性のみ」の同性ペアで探索する（枯渇ベース、8.1節）。

なお、作成後の見直し（8.5a節）では、同一課・ペア重複を**新たに作る入替えは行わない**。例外は
「今期0回の職員に初めての出番を作る」場合だけで、これは除外の多い課で窓の狭い職員が同じ課に
固まっており、同一課を一切許さないとその職員が0回のまま終わってしまうためである。

### 8.4a 性別ゾーン（女性ゾーン→男性ゾーンの一方向切替）

処理期の中で「女性ゾーン」「男性ゾーン」という状態を持ち、**女性が本当に使い切られたら、その処理期の残りは女性を一切探索しない**（一方向のみで、女性ゾーンへは戻らない）。男性の期間の途中に女性が単発で混ざると担当交代がしづらくなるため、ゾーンをまたいだ混在を構造的に起こさないようにしている。

| ゾーン | 探索順 |
| --- | --- |
| 女性ゾーン | ①女性・今期未割当 のみ |
| 男性ゾーン | ②男性・今期未割当 → ③男性・今期2回目 → ④最終手段（男性に固定したまま、係長級の有無・最低間隔日数を緩和） |

**ゾーンが恒久的に切り替わる条件＝「割当可能な女性職員が、この処理期内で全員すでに1回以上割り当て済みになったこと」（女性が本当に使い切られたこと）。** その日に限って割り当てられる未割当の女性がたまたま0人だった（休暇・行事除外等の日付固有の事情）というだけでは、ゾーンは切り替わらない。①が失敗した日は、その日だけ男性ゾーンの②〜④を借りて埋め、翌日以降も女性ゾーンのまま①から探し直す。女性が本当に使い切られた日に限り、その日から男性ゾーンへ恒久的に切り替わり、以後この処理期では女性を二度と探索しない。

*（旧仕様との違い）* 以前は「その日に割り当てられる未割当の女性が1人もいない」という**日付固有の事情**だけでゾーンを恒久的に切り替えていたため、行事除外・育休等が特定の1日だけ女性側に重なる偶然が起きると、その1日を境に処理期の残り全体が男性ゾーンに固定され、実際にはまだ多く残っている未割当の女性職員が処理期の残り全日程から除外されて0回のまま終わる一方で、男性側の同じ職員が2回目・3回目と繰り返し割り当てられる、という偏りが生じていた。「本当に使い切られたか」で判定するよう変更し、この偏りを解消した。

**②〜④のいずれも失敗した場合（＝そもそも男性が存在しない、または全員が対象外）は、ゾーンを切り替えても意味がないため、女性側の「今期2回目」・最終手段（女性に固定したまま係長級の有無・最低間隔日数を緩和）を試す。** この場合、女性ゾーンにとどまり続ける（全員女性の職場等での安全策）。

**安全弁：** 女性を一度も使っていない状態（＝処理期の冒頭、まだ女性ゾーンが実質的に始まっていない状態）では固定しない。女性を一度でも使ったあとで、かつ女性が本当に使い切られている場合に限り、男性ゾーンへの切替がその処理期の残り全体に定着する。

前半・後半に分けて処理期を作成する場合など、続きを生成する際は、その処理期の確定済み履歴から性別ゾーンの状態を復元する（履歴に女性が含まれていれば「女性を使用済み」とし、加えて割当可能な女性職員が履歴上ですでに全員使い切られている場合に限り「男性ゾーン」として開始する）。

**性別ごとの日数の枠は設けない。** 各性別に割り当てられる日数は、その処理期の男女の人数に応じて自然に決まる（女性が少ない職場では、女性ゾーンの期間が短く、男性ゾーンの期間が長くなる）。

性別を固定した1日分の探索は、次の順で行う（各段階は同性ペア・常時除外・育休等・退職予定日・新規採用の除外を一切崩さない）。

| 段階 | 1人目 | 今期未割当 | 最低間隔日数 | 所属除外（月別・行事別） |
| --- | --- | --- | --- | --- |
| ① | 係長級 | 2名とも | 厳守 | 厳守 |
| ② | 係長級 | 2名とも | 緩和（8.3.3a） | 厳守 |
| ③ | 係長級または**市民課経験者**（8.3.3b） | 2名とも | 厳守 | 厳守 |
| ④ | 係長級または市民課経験者 | 2名とも | 緩和 | 厳守 |
| ⑤ | 係長級 | 片方だけ（もう片方は2回目以降） | 厳守 | 厳守 |
| ⑥ | 係長級 | 片方だけ | 緩和 | 厳守 |
| ⑦ | 係長級または市民課経験者 | 片方だけ | 厳守 | 厳守 |

**「2名とも今期未割当」を「誰かの2回目」より常に優先し**（③④が⑤⑥より先）、**「係長級を1人目に置く基本の形」を「市民課経験者が資格要件を満たす形」より優先する**（①②が③④より先）。**所属除外の緩和（⑨）は最低間隔日数の緩和より後**＝①〜⑧を所属除外だけは守ったまま全て試し尽くしてから、初めて所属除外を緩和して①〜⑧をもう一度試す（8.3.3c）。それでも見つからない場合に限り、既に割当済みの職員へ2回目を回す（⑩）。第①〜⑨段階は「今期まだ割り当てていない職員を1名でも含むペア」を探す段階で、**性別ゾーンの境界判定にもこの第①〜⑨段階を使う**（いずれでもその性別のペアを作れなくなった日から、他方の性別を探す）。第⑩段階以降は、他方の性別でも埋められなかった場合にのみ使う。

すべての段階を通したあと、勤務表全体を見渡した入替えによる見直し（8.5a節）を行う。

### 8.4b 人数不足時の最終手段（ゾーン内に固定）

女性ゾーン・男性ゾーンいずれの場合も、8.4a節の最終手段（③④、または女性側の同等の最終手段）は**その時点のゾーンの性別に固定したまま**行う。性別を問わない・他方の性別で埋める、という処理は行わない。

| ケース | 割当内容 | 状態 |
| --- | --- | --- |
| 係長級がいる（ゾーン内） | その係長級と、担当回数の少ない同性の候補を組み合わせる | 要確認：人数不足のため、通常のルールを緩和して割り当てました |
| 係長級が1名もいない（ゾーン内） | 担当回数の少ない同性の候補2名を組み合わせる | 要確認：係長級が含まれていません（人数不足のため） |
| ゾーン内の対象者が1名しかいない | その1名のみを割り当てる | エラー：人数不足のため1名のみの割当です |
| ゾーン内の対象者が1名もいない | 誰も割り当てない | エラー：対象者がいません |

**男性ゾーンで男性が本当に枯渇した日は、女性で埋めずにエラー（赤色）とする。** 女性混入をゼロにすることを、人数不足によるエラー表示の発生よりも優先した設計判断である。

この最終手段は、緩和の少ない順に次の4通りを試す：①通常どおり（最低間隔日数を守り、選挙管理委員会併任者も除外） → ②最低間隔日数のみ緩和 → ③選挙管理委員会（併任）の除外のみ緩和 → ④両方緩和。2名の組合せが作れる緩和がどこかで見つかれば、そこで確定する（1名のみの割当は、より緩和すれば2名の組合せが作れる可能性があるため、4通りすべてで2名の組合せが作れなかった場合にのみ採用する）。②で割り当てた場合は「要確認：前回勤務日から120日未満の職員を含みます（人数不足のため）」、③④で選挙管理委員会併任者を割り当てた場合は「要確認：選挙管理委員会事務局（併任）の職員を人数不足のため特例的に割り当てました」を表示する（性別は変えない）。

この最終手段により2名の枠が埋まった場合は「要確認」（黄色）、1名のみ・0名の場合は「エラー」（赤色）として状態欄に表示する。

### 8.5 候補の優先順位

1人目（係長級）の候補は、資格要件を満たす者を優先しつつ、次の順で並べて先頭から評価する。

1. 累計担当回数の少なさ（担当履歴のない職員を最優先）
2. 残り出番機会の少なさ（**その日以降に**、月別課除外ルール・行事の除外期間・育休等・退職予定日・新規採用の除外という**静的な**制約だけで見て何日割当可能か。性別ゾーンや120日間隔等、割当の進行に応じて変わる動的な制約は含めない。課除外ルールや行事に当たりやすく出番の窓が狭い職員を、その窓のうちに優先的に割り当てるためのもの。**処理期全体の固定値ではなく、日が進むごとに「その日以降の残り日数」へ更新する**。固定値のままだと、例えば窓が9月にしかない職員の優先度が4月時点と9月直前とで変わらず、窓が閉じる直前になっても優先されないまま処理期が終わってしまうため）
3. ランクの大きさ（値が大きい＝下位の職員を優先。CSV取込等でランクが不明な職員は、実在する最大のランクより大きい値として扱い、下位の職員と同様に優先する）
4. 年齢の若さ（CSV取込等で年齢が不明な職員は、実在する最小の年齢より小さい値として扱い、若手と同様に優先する）
5. 前回勤務日の古さ

*（優先順位の並び順について）* 残り出番機会は**ランク・年齢より前**で判定する。ランクや年齢を先に比較すると、担当回数が同じ職員同士ではランク差・年齢差だけでほぼ毎回決着してしまい、残り出番機会が実質的に一切参照されない状態になってしまう。その結果、課除外ルールや行事の除外期間で出番の窓が狭い職員が、たまたまランクや年齢で負け続けて割当機会をすり抜けたまま処理期を終えてしまう（＝一度も割り当てられないまま、他の職員だけが2回目・3回目と繰り返し割り当てられる）ことがあった。残り出番機会をランク・年齢より優先させることで、出番の窓が狭い職員がその窓のうちに確実に割り当てられるようにしている。

2人目の候補（係長級・主事級を問わない）も、**級による優先は行わず**、上記の1〜5と同じ順で並べて評価する。これにより、係長級2名の組合せと係長級＋主事級の組合せが、担当回数等の実績に基づいて対等に扱われる。

累計担当回数による並べ替えにより、ある処理期で割り当てられなかった職員は次の処理期で優先される。ランクによる並べ替えにより、同じ担当回数であれば階級の高い職員ほど結果的に日直の割当が少なくなりやすい。

決定したペアが係長級2名の組合せの場合、勤務表の表示順（1人目／2人目）は、ランクの値が低い方（役職が上の方）を1人目に、同ランクなら年齢が上の方を1人目に並べ替える（割当の資格判定には影響しない、表示順のみの並べ替え）。係長級・主事級が混在するペアは、係長級のランク（400〜600）が主事級のランク（601〜999）より必ず低いため、もともと係長級が1人目になっており対象外。

### 8.5a 作成後の見直し（最適化パス）

自動作成は日付順に1回だけ通す方式のため、後の日ほど枠が埋まった状態で判定される。その結果、「その職員が入れたはずの数少ない日」が先に別の職員で埋まってしまうと、後から挽回する手段がなかった。そこで、作成し終わった勤務表の**全体を見渡して、絶対条件を一切崩さない入替えだけを試し、全体が良くなる場合に限って採用する**見直しを、作成のたびに自動的に行う。

**この見直しでも決して崩さない条件（絶対条件）**

- 同性ペア。**その日の性別ゾーン**（女性の日／男性の日の別）も原則変えない。唯一の例外は「女性の2回目だけで埋まっている日を、今期未割当の男性2名に差し替える」場合で、この場合に限り女性の日→男性の日への変更を認める（後述。男性の日→女性の日への変更は認めない）
- 育休・産休・病気休暇等の除外期間（産休終了後の育休みなしを含む）・特例の除外（個別、8.3.4c）
- 常時除外（派遣・7割措置・秘書係・運転手・常時除外所属）
- 月別の課除外ルール・行事の除外期間
- 選挙管理委員会事務局（併任）の除外期間
- 新規採用職員の除外・退職予定日の除外
- 年末年始・GWの重複回避
- 同じ日の2枠に同じ職員を入れない
- **資格要件（係長級または市民課経験者）を満たさない日を新たに作らない**（既にそうなっている日を改善する入替えは可）
- **勤務間隔を14日より詰めない**（もともと14日未満の日をさらに詰めることもしない）
- **係長級を含む日から係長級を外さない**。ただし「今期0回の職員に出番を作る場合」と「担当回数の上限（8.3.16）を超えている職員の負担を減らす場合」に限り、外すことを許す（全員に出番を作ること・担当回数の偏りをなくすことを優先するため）
- **担当回数の上限（8.3.16）を超えて回数を増やさない**（もともと上限を超えている職員をさらに増やすこともしない）
- **同一課の組合せ・過去のペアとの重複を新たに作らない**（8.3.11・8.3.13。既にそうなっている日を改善する入替えは可）。例外は「今期0回の職員に初めての出番を作る」場合だけで、除外の多い課では窓の狭い職員が同じ課に固まっており、同一課を一切許さないとその職員が0回のまま終わってしまうため

**良くなったかどうかの評価（重い順）**

| 評価する内容 | 重み |
| --- | --- |
| 今期1回も割り当てられていない職員 | 1000／人（＋出番の窓が狭い職員への上乗せ。後述） |
| 埋まっていない枠（1名のみ・0名の日） | 500／枠 |
| 資格要件（係長級・市民課経験者）を満たさない日 | 400／日（新たに作ることは禁止） |
| 勤務間隔が目安より詰まっている度合い | 200×不足の割合（後述） |
| 係長級が1名も含まれない日（市民課経験者が資格を満たしていれば可） | 200／日 |
| 担当回数の偏り（担当回数−1の2乗に比例。3回目・4回目ほど重い） | 60 |
| 過去のペアと重複／同じ組合せの繰り返し | 30／件 |
| 同一課の組合せ | 25／日 |
| 課長補佐・副主幹の組合せ | 20／日 |

**出番の窓（置ける日数）の考慮**：所属除外（月別課除外・行事の除外期間）や育休等に当たりやすい職員は、その処理期に置ける日が数日しかないことがある。その数日を「他にも入れる日がたくさんある職員」に先に取られると、以後どこにも入れられず0回のまま終わってしまう。そこで見直しでは次の3点で「出番の窓」を考慮する。

- 今期0回の職員を入れる際、**窓が狭い職員から順に**席を確保する
- 担当回数の多い職員の枠を譲る相手を選ぶ際、担当回数が同じなら**窓が狭い職員を優先**する
- 今期0回の職員1人あたりのコスト（1000）に、**窓の狭さに応じた上乗せ**（200÷窓の日数、最大200）を加える。窓が2日の職員と、まだ何日も入れる職員とを同じ1000で評価すると、その2日を後者に取られている状態からの入替えがコスト中立（±0）になって採用されず、窓が狭い職員だけが0回のまま残ってしまうため。窓が0日（どこにも置けない）の職員には上乗せしない

**勤務間隔の評価の基準**：最低間隔日数（例120日）は、対象日数に対して職員が少ない処理期では最初から届かないことが多い。そこで、その職員が**現実に確保できる間隔の目安＝処理期の日数÷その職員の担当回数**（例：176日の処理期で2回なら88日）を基準とし、そこからの不足の割合（0〜1）で評価する。これにより「51日を88日に広げる」といった実際に効く改善が正しく評価される。

**入替えの試し方**（この順に繰り返し、改善できなくなるまで続ける）

1. 今期0回の職員を、空き枠または担当回数の多い職員の枠に入れる
2. **玉突き（連鎖）入れ替え**：1で入れられなかった職員を、担当者を順にずらす連鎖で入れる（後述）
3. **女性の2回目だけで埋まっている日を、今期未割当の男性2名に差し替える**（後述）
4. 担当回数が多い職員の枠を、担当回数の少ない職員に譲る
5. 要確認が付いている日について、**同じ性別ゾーンの別の日**と担当を交換する

**玉突き（連鎖）入れ替え**：今期0回の職員Xを入れたい枠が、担当回数の多い職員の枠と重ならないことがある（Xの除外期間の都合で、Xが入れる日が限られているため）。この場合、1対1の入れ替えではどうにもならずXは0回のまま終わってしまう。そこで、担当者を順にずらしていく連鎖を**最大5段**まで探す（人が手作業で組んでいたときの手順に合わせた段数）。

- 例：X→（Xが入れる日D。担当者はZ）／Z→（Zが入れる日D2。担当者はY＝複数回割当）の2段で、Xの0回とYの複数回割当が同時に解消する
- 連鎖は「空き枠に収まった」または「複数回割り当てられている職員を外せた」時点で完成とし、**連鎖全体をまとめて1つの入替えとして評価する**（途中経過だけが残ることはない）
- 各段では、その職員が実際に置ける枠だけを、見込みの良い順（空き枠→担当回数の多い職員の枠→その他）に一定数まで試す。同じ職員・同じ枠を1つの連鎖の中で二度使わない
- 空き枠も複数回割当の職員も存在しない名簿（対象日数に対して職員が多く、全員が1回ずつで埋まっている等）では、何段掘っても連鎖は成立しないため探索そのものを行わない
- 探索するノード数には上限があり、必ず終了する（同じ入力からは必ず同じ結果になる）

**女性の2回目だけの日の差し替え**：女性の日で2名とも今期2回目以降になっている日は、今期未割当の男性2名に差し替えることで、女性の2回目が2件減り男性2名に初めての出番が回る。次の場合は差し替えない。

- 差し替える男性に今期2回目以降が混じる場合
- 外す女性のどちらかが今期0回になってしまう場合（＝外す2名がどちらも今期2回目以降であることを条件とする）
- 同一課・過去のペアとの重複・資格要件など、他の条件を新たに崩す場合

探索の順序はすべて固定されており、**同じ入力からは必ず同じ結果になる**（実行するたびに結果が変わることはない）。入替えが起きた日と、担当が動いた職員が関わる日については、「状態」と「理由」を最終的な組合せから作り直すため、表示と実際の組合せが食い違うことはない。

見直しの結果は、勤務表作成タブの結果一覧の下に表示する。入替え件数に加えて、**改善したもの**（未割当者・1人あたりの最大担当回数・同一課・ペア重複など）と、**引き換えに増えたもの**を分けて表示する。全員に出番を作ること・担当回数の偏りをなくすことを優先する設計のため、その代わりに「係長級が含まれない日」が増えることがあり、それも隠さずに表示する。作成後に手動で入れ替えた場合は、この表示は実態と合わなくなるため消える。

### 8.6 市民課経験の判定

以下のいずれかに該当する場合、市民課経験ありとする。

1. 名簿上で「市民課経験」がオンになっている
2. 現在の所属名に「市民課」を含む
3. 所属履歴に「市民課」を含む所属がある

なお、Excel名簿の取込時に上記2に該当する職員は「市民課経験」が自動的にオンになり、以後の処理期にも引き継がれる。

### 8.7 未割当職員の理由判定

今期まだ割り当てられていない対象職員について、対象日ごとに以下を積み上げて理由を表示する。

| 理由 | 判定 |
| --- | --- |
| 性別が未設定 | 性別が設定されていない |
| 育休・産休等の除外期間中 | 対象日が登録された除外期間内 |
| 特例の除外に該当（理由：◯◯） | 対象日がルール設定タブで個別に登録した特例の除外期間内（8.3.4c節）。育休・産休等とは区別して、登録した理由文をそのまま表示する |
| 所属の除外ルールに該当 | 対象日に所属が月別・行事別の除外対象 |
| 選挙管理委員会事務局（併任）のため選挙関連の除外期間中 | 対象日が、選挙管理委員会併任者を対象にした行事の除外期間内 |
| 採用から6ヶ月未満 | 対象日が採用日＋6ヶ月より前 |
| 退職予定日の1ヶ月前を過ぎている | 対象日が退職予定日から設定ヶ月数を引いた日より後 |
| 前回勤務日から120日未満 | 対象日が前回勤務日＋120日より前 |
| 年末年始・GWの重複回避 | 対象日が年末年始・GWで、過去の同期間の担当者に該当する |
| 今期の割当枠が埋まった | 候補ではあったが、他の職員が優先された |
| 自分のゾーンでなかった日 | その日は性別ゾーン（8.4a節）が自分の性別ではなかった（「女性ゾーンでなかった日」／「男性ゾーンでなかった日」として表示） |

本機能は完全なシミュレーションではなく、職員個人の属性による除外の積み上げによる推定である。同一課回避・ペア重複回避などペア単位の制約は理由に反映せず、「今期の割当枠が埋まった」に含まれる。

### 8.8 交換ペアの検出とマーカー表示

「交代を反映」を適用するたびに、変更ログ（変更前職員ID・変更前氏名・変更後職員ID・変更後氏名・対象日・欄（係長級／主事級）・記録日時）を1件追加で記録する。この変更ログとは別に、履歴（history）自体は従来通り変更後の職員のみを保持し、変更前の職員IDは変更ログにのみ残る。

交換ペアの検出は以下の手順で行う。

1. 同じ「対象日＋欄」の組合せに複数回の変更ログがある場合、最も新しい記録日時のものだけを、その枠の「現在有効な変更」として扱う。
2. 対応する履歴（history）の行が既に削除されている変更ログは対象から除外する。
3. 残った「現在有効な変更」同士を総当たりで比較し、変更ログAの変更前IDが変更ログBの変更後IDと一致し、かつ変更ログAの変更後IDが変更ログBの変更前IDと一致する組合せを「交換ペア」とする（＝2人が互いの担当日を交換した状態）。
4. 検出した交換ペアには、あらかじめ用意した10色の配色から順に色を割り当てる（ペアが10組を超える場合は色を再利用する）。

検出された交換ペアは、確定済み履歴一覧（6.6.1節）と確定済み履歴PDF・勤務表PDF（7.5節）の両方で、対象セルの氏名の前に同じ色の丸印マーカーとして表示する。マーカーにカーソルを合わせる（または画像上で確認する）と、交代相手の氏名と日付を確認できる。

この機能追加より前に適用された「交代を反映」には変更ログが存在しないため、交換ペアとして検出されない。

| 8 | 係長級2名でペアを組む場合、双方の職名が「課長補佐」「副主幹」のいずれかに該当する組合せ（課長補佐＋課長補佐／課長補佐＋副主幹／副主幹＋副主幹）は避ける |
