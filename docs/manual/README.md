# 操作マニュアルの作り方

`docs/日直勤務表アプリ_操作マニュアル.pdf` を作り直すためのファイル一式です。
マニュアル本体を読むだけなら、PDFをそのまま開いてください。

## 構成

| ファイル | 役割 |
| --- | --- |
| `マニュアル.html` | マニュアルの本文。文章を直すときはここを編集します |
| `images/` | 本文に貼る画面キャプチャ（`fig<章>-<番号>.png`） |
| `build_manual.js` | HTMLからPDFを生成する |
| `shots.js` | アプリを実際に動かして画面キャプチャを撮り直す |
| `demo_data.js` | キャプチャに使う架空の職員名簿・処理期・行事・休暇 |

画面の写真はすべて `demo_data.js` の**架空のデータ**で撮っています。実在の職員は含まれません。

## 文章だけを直す場合

`マニュアル.html` を編集して、PDFを作り直します。

```bash
node docs/manual/build_manual.js
```

`docs/日直勤務表アプリ_操作マニュアル.pdf` が上書きされます。

## 画面キャプチャを撮り直す場合

アプリの画面を変更したときは、キャプチャも撮り直します。
アプリをローカルで配信した状態で `shots.js` を実行してください。

```bash
# 1. アプリを配信する（プロジェクトのルートで）
python3 -m http.server 8899

# 2. 別のターミナルでキャプチャを撮る
node docs/manual/shots.js

# 3. 撮れた画像を images/ に配置してPDFを作り直す
#    （shots.js の出力先は scratchpad なので、fig<章>-<番号>.png の名前でコピーします）
node docs/manual/build_manual.js
```

`shots.js` は、デモデータの投入 → 勤務表の作成 → 確定 → バックアップ書出 → 復元 →
交代の反映、までを実際に操作して各場面を撮影します。

## 必要なもの

- Node.js と Playwright（Chromium）
- 日本語フォント（IPAゴシック等）。入っていないとPDFの日本語が豆腐になります

## 注意

- Playwright の `setInputFiles` は**日本語のファイル名を無視する**ため、
  `shots.js` の中では復元用のバックアップを ASCII 名（`backup_demo.json`）で保存しています。
  アプリが実際に書き出すファイル名は日本語のままで問題ありません。
- 図の高さは、本文幅180mm換算でA4の1ページ（約245mm）に収まるようにしてください。
  収まらないと `page-break-inside: avoid` が効かず、図が2ページに割れます。
