# マニュアルの作り方

このフォルダには2冊のマニュアルの原稿が入っています。読むだけならPDFをそのまま開いてください。

| PDF | 読む人 | 内容 |
| --- | --- | --- |
| `docs/日直勤務表アプリ_操作マニュアル.pdf` | 勤務表の担当者 | アプリの使い方（復元・作成・交代の反映） |
| `docs/日直勤務変更_申請手順.pdf` | 申請する職員 | Garoonでの変更届の出し方（5ステップ） |

以下はまず**アプリの操作マニュアル**についての説明です。申請手順のほうは末尾を参照してください。

## 操作マニュアル（アプリの使い方）

## 構成

| ファイル | 役割 |
| --- | --- |
| `マニュアル.html` | マニュアルの本文。文章を直すときはここを編集します |
| `images/` | 本文に貼る画面キャプチャ（`fig<章>-<番号>.png`） |
| `build_manual.js` | HTMLからPDFを生成する |
| `shots.js` | アプリを実際に動かして画面キャプチャを撮り直す |
| `demo_data.js` | キャプチャに使う架空の職員名簿・処理期・行事・休暇 |

画面の写真はすべて `demo_data.js` の**架空のデータ**で撮っています。実在の職員は含まれません。

## 文章だけを直す場合

`マニュアル.html` を編集して、PDFを作り直します。

```bash
node docs/manual/build_manual.js
```

`docs/日直勤務表アプリ_操作マニュアル.pdf` が上書きされます。

## 画面キャプチャを撮り直す場合

アプリの画面を変更したときは、キャプチャも撮り直します。
アプリをローカルで配信した状態で `shots.js` を実行してください。

```bash
# 1. アプリを配信する（プロジェクトのルートで）
python3 -m http.server 8899

# 2. 別のターミナルでキャプチャを撮る
node docs/manual/shots.js

# 3. 撮れた画像を images/ に配置してPDFを作り直す
#    （shots.js の出力先は scratchpad なので、fig<章>-<番号>.png の名前でコピーします）
node docs/manual/build_manual.js
```

`shots.js` は、デモデータの投入 → 勤務表の作成 → 確定 → バックアップ書出 → 復元 →
交代の反映、までを実際に操作して各場面を撮影します。

## 必要なもの

- Node.js と Playwright（Chromium）
- 日本語フォント（IPAゴシック等）。入っていないとPDFの日本語が豆腐になります

## 注意

- Playwright の `setInputFiles` は**日本語のファイル名を無視する**ため、
  `shots.js` の中では復元用のバックアップを ASCII 名（`backup_demo.json`）で保存しています。
  アプリが実際に書き出すファイル名は日本語のままで問題ありません。
- 図の高さは、本文幅180mm換算でA4の1ページ（約245mm）に収まるようにしてください。
  収まらないと `page-break-inside: avoid` が効かず、図が2ページに割れます。

## 申請手順（Garoonでの変更届の出し方）

`docs/日直勤務変更_申請手順.pdf` を作り直すためのファイルです。
元はNotebookLMで作られた資料で、その体裁（16:9・7面・暗転＋オレンジの矢印）をそのまま引き継いでいます。

| ファイル | 役割 |
| --- | --- |
| `申請手順.html` | 本文。16:9・7面（表紙＋5ステップ＋まとめ） |
| `annotate.py` | キャプチャを暗転させ、操作箇所に矢印・番号を焼き込む |
| `build_apply.js` | HTMLからPDFを生成する |
| `images/garoon/garoon1〜6.png` | 無加工のキャプチャ（撮ったものをそのまま置く） |
| `images/garoon/step1〜step5.png` | `annotate.py` が作る注釈入り。HTMLが読むのはこちら |

```bash
python3 docs/manual/annotate.py   # 先に注釈を焼き込む
node docs/manual/build_apply.js   # PDFを作る
```

### キャプチャを撮り直したとき

`images/garoon/` に次の名前で置き直してから、上の2コマンドを実行します。

| ファイル名 | 画面 |
| --- | --- |
| `garoon1.png` | ワークフロー（最新一覧） |
| `garoon2.png` | 申請フォームの選択（カテゴリー一覧） |
| `garoon3.png` | 申請フォームの選択（人事関連） |
| `garoon4.png` | 申請の作成（内容の入力） |
| `garoon5.png` | 申請の作成（経路の設定） |
| `garoon6.png` | 申請の作成（内容の確認） |

- `garoon2` と `garoon3` は、全画面のままだと文字が小さく読めないため、
  カテゴリー一覧の部分だけを切り出しています（元画像の上から205px、左から680pxまで）。
- **`annotate.py` の `TARGETS` に書いてある座標も直してください。**
  画面の見た目が変わると、矢印やオレンジ枠が別の場所を指してしまいます。
  座標はキャプチャの左上を原点とするピクセル値です。

### 注意

- **Garoonの画面は、必ず実物のスクリーンショットを使ってください。**
  生成AIに画面を描かせると、実在しないメニューや誤った氏名・日付が入った画像ができます
  （この資料は、そうして作られた版を作り直したものです）。
- 本文は `変更する日付 = 2026年10月03日（土）`、`交代相手氏名 = 上部　裕子` の例で書かれています。
  撮り直したキャプチャの内容と食い違わないか確認してください。
